## How to use (humans and agents)

1. **One “next”** — exactly one row in Active has status **Next**; everything else is **Queued**, **In progress**, **Open**, **Held**, **Blocked**, or **Parked**.
2. **Order can change** — reprioritize Active rows when dependencies or findings require it; reconcile every `WQ-xxx` before and after (nothing deleted — see `generic-work-queue-discipline.mdc`).
3. **New findings** — add to **Inbox** first; triage into Active / Parked / Done in the same session when possible.
4. **Replacing a list** — update this file; do not drop IDs. Mark old rows **Superseded by WQ-xxx** in Notes if merged.
5. **Audit run Fix/Improve** — ephemeral per `run_audit.cmd`; recurring engineering debt from reviews lives in **Engineering backlog** below.
6. **Product features** — not here; bootstrapped apps use `docs/ROADMAP.md`. This queue is **maintainer / pack / agent-process** work.

## Lessons that outlived their release

Absorbed from the retired session doc (2.22.65). The bump-by-bump history is in
`pack/docs/AUDIT_SYSTEM_CHANGELOG.md`; each Done row below carries its own evidence. What is worth
carrying forward is the handful of findings that generalise past the bump that produced them.

- **Testing the layer below the one users touch proves nothing about the one they touch.** Forty-seven behavior steps called each `.ps1` with `-NoPause` while four root `.cmd` launchers sat on bare `pause` statements — the layer a human double-clicks and an agent runs.
- **Verifying delivery is not verifying arrival.** Every guard on the global rules confirmed 13 files sat in `%USERPROFILE%\.cursor\rules\`; none asked whether anything reads that folder. Cursor never documented it as a rule location, so the answer was no, and two `alwaysApply: true` rules were inert for months behind a green `doctor.ps1`. When a feature's value depends on *another program* consuming an artifact, the test has to observe that program's behavior — presence at the hand-off point is the one thing that was never in doubt.
- **Measure the surface before agreeing to a sweep.** "Remove git from all of this" looked like 279 mentions across 38 files. It was about a dozen functional calls, all of which already handled git's absence, plus a handful of documents telling a human to run git commands. The other ~200 were historical record and rationale comments, where a rewrite would have destroyed the evidence rather than fixed anything.
- **A relaxed requirement leaves dependents behind.** Demoting CI's execute-bit assertion to informational immediately falsified nine other CI invocations that ran wrappers as `./x.sh` — they depended on the mode that had just stopped being guaranteed. When you stop promising a property, grep for everything that consumes it in the same pass.
- **A maintainer script that runs the verifier cannot be called from the verifier.** A new behavior step shelled out to `doctor.ps1`; doctor calls `verify-audit-system.ps1`, which runs the behavior suite, which called doctor. Twelve process levels deep, 25 minutes, killed — and six `orphan-rule-probe-*` directories left behind as the count of re-entries. Neither file is wrong when read alone, which is why only a run could find it. Fix: extract the logic so the step tests it in-process, and add an arm asserting **no** step invokes doctor.
- **When several fixes each look sufficient, count the defects before picking one.** Four plausible one-step fixes were on the table for an inert rule file, and the reason none was right is that there were three defects — undelivered content, a false self-description, and no detection — and each option closed exactly one. "Which of these should I do" was the wrong question; "how many separate things are broken" was the right one.
- **Delete is an endpoint, not a fix, until something has replaced the function.** Deleting the inert rule first would have removed the evidence and the content while leaving the gap that let it exist. It became correct only after the content lived in a load path and a check could catch the next one.
- **A harness that reports failures can itself be the failure.** A verify sweep reported `sync-audit-system.ps1` and `sync-portable-docs.ps1` as exit 1 while both exited **0** when invoked directly. Cause: `$a = switch (...) { 'x' { @('-VerifyOnly') } }` returns a **`String`** for a one-element clause and an **`Object[]`** for a two-element one, and `@a` splatting a scalar passes garbage the script rejects. The eight scripts that "passed" did so because their argument arrays had two elements and survived. Two false alarms and eight results that were right by luck — before reporting a red result, check the measurement is capable of a green one, which is WQ-443 pointed at the tooling instead of the guard.
- **"Absent" and "unreadable" are different states, and a guard that handles one may fail the other.** Every git guard here was verified against a tree with `.git` *removed*, passed, and was described as guarding "for absence" — accurately. Deleting the real `.git` left a locked directory behind, the path tests fell through, and the audit failed on a pack certified an hour earlier as git-optional. A test that removes a thing cannot observe the states where the thing is present but broken: absent, unreadable, wrong type (a `.git` **file** is a worktree), and corrupt are four cases, not one.
- **Filters that run after a walk cannot prevent the walk.** `Copy-Tree` listed `.git\` in `SkipDirNames` for releases and still died on an unreadable `.git\logs`, because every filter was applied per file once enumeration had already entered the directory. If a skip list is meant to protect against a directory being *unenterable*, the tolerance has to be on the enumeration itself.
- **Count from the diff, not from the edits you remember making.** The first tally of that conversion said seven and the diff said nine: a `run: ./run_audit.sh` one-liner and an `if ./Bootstrap-Project.sh; then` conditional both sit outside the shape a `^\s*\./` scan matches, and both were converted without being counted. A number in a changelog is a claim like any other and has to come from a command.
- **A doc sweep that greps prose does not reach text assembled by code.** 2.22.79 corrected the "global rules load from the profile folder" claim in ~15 documents. It reappeared the same day in `pack/docs/portable/GENERIC_RULES.md`, because that file is *generated* and the claim lived as a string literal in `sync-portable-docs.ps1`. Grepping `*.md` reads the output of the last build, never the instruction that produces the next one.
- **A claim can be distributed across structure, where no single line contains it.** The offending markdown row said only "Cursor (after `install.ps1`)"; the header two rows above supplied "Load path". Line-at-a-time scanning is not unlucky against this shape, it is incapable of it — a scanner has to carry table context, and a disclaimer window wide enough for wrapped prose.
- **A generated artifact cannot be tested by editing the generated artifact.** Planting a defect into `GENERIC_RULES.md` produced a clean pass: an earlier step regenerated the file mid-suite and repaired the plant away before the guard read it. The plant belongs in the generator, which is also the real regression path. Seventh instance of the WQ-443 shape, and the first where the masking step was a *repair* rather than a filter.
- **A check that a file exists is not a check that it is right.** The cited-paths check proved a template was present; only bootstrapping a project showed it produced a README titled `{{PROJECT_NAME}}`.
- **A guard narrower than the thing it guards reports success on a broken artifact.** `verify-agent-setup` checked 5 of 12 profile rules and 10 of 174 pack files; the export's completeness guard passed an archive missing seven launchers. None was *wrong* — each was too narrow.
- **A read that never returns raises nothing.** The Cursor session hook promised to fail open on any error and drained stdin with an unbounded `ReadToEnd()`. Cursor closes that handle, so it passed for four releases; bash leaves it open, and the audit hung sixteen minutes. `try/catch` is not a timeout.
- **Diagnose a stall from CPU time, not elapsed time.** What proved that hang was blocked rather than slow: `pwsh` holding 3 seconds of CPU after 16 minutes, with idle children.
- **Plant the defect you mean, and prove it parses.** A negative test whose planted defect was a *syntax* error made the guard look proven when it was not. A planted defect is a test input — verify it is the input you intended.
- **Prefer executing a path over reading it.** Steps 40–43 grepped the `.sh` wrappers for marker text for four releases; the first real `bash` run found a hang in seconds.
- **Assert on the artifact, not the plumbing.** The first fix for the double-encoded agent manifest pinned `PYTHONIOENCODING` and changed nothing, because the JSON was already ASCII-escaped. The test that works reads an em dash out the far end.
- **A checker without exclusions gets muted within a week.** The cited-paths discovery pass produced 52 candidates and exactly one defect; the other 51 were project-relative paths, a deliberately forbidden file, and regex artefacts.
- **Green here is not green anywhere.** Several tests were grading the machine rather than the pack. Tests that touch install state must build their own scratch install and honour `AGENT_STARTER_PACK_INSTALL_ROOT`.
- **A garbled console is not a corrupted file.** Terminal output here shows em dashes as mojibake under the default codepage. Check bytes before reaching for a repair script.
- **The mirror runs one way, source → installed.** A stale install must never overwrite the pack folder or resurrect deleted files; cross-filesystem mtimes (exFAT local vs NTFS UTC) make "newest wins" unsafe.
- **A deferred item that shipped is worse than no list**, and a gap documented in three places but tracked in none still gets forgotten. Both directions are why this file exists.
- **A tripwire calibrated to the wrong value is worse than none** — it fires on the healthy state and stays quiet on the broken one.
- **Default working copies have no `.git`, and that is the intended state** (WQ-459). The audit's test-pass proof is therefore `tree:<hash>` with no commit prefix, `verify-work-queue.ps1` reports `[SKIP] not a git checkout` for its Done-log-versus-history arm, and `run_audit_core.ps1` skips the committed-build-output check. All of that is designed behavior. Publish and CI require StarterPack-Airlock on the host Desktop.
- **A proof can be defeated by the thing it is proving.** The mutation runner's first real execution reported step 72 as not proven. Step 72 guards **failure attribution**, so its mutation disables the code `Fail` uses to record which step failed: the suite went red exactly as intended and wrote every failure with no step attached, leaving the runner unable to name what it had broken. The fix is to move the measurement outside the blast radius — record the raw line, and re-attribute using the *measuring* side's own unmutated code, taking only the text from the mutated copy. Generalizes to any self-testing system: when the thing under test is the reporting channel, the report must not travel through it.
- **A measurement of a tree that is being edited is a measurement of no tree.** Two unrelated steps failed in two of three mutated runs and read convincingly as collateral from a too-broad mutation. They were a version bump being edited while the runner took its per-entry copies, so the copies were not the same pack. Cost: a wrong diagnosis ("narrow the mutation") that would have changed working code. Long-running tools that snapshot a working tree should fingerprint it at both ends and say so when it moved; and the operator should stop typing.
- **A zero that means "unknown" is worse than an error, because it is a valid answer.** Step 72's live check read its own line with `$MyInvocation.ScriptLineNumber`, which is **0** at top-level scope. Nothing threw: 0 resolved cleanly to "before every announcement", the attribution came back empty, and the step failed pointing at the announcement map — which was correct. The mechanism it was checking had already got the same answer right, from the call stack, in the same run. A probe had printed the 0 an hour earlier and it was not applied. Two habits close this: when two paths need the same fact, have them call **one** helper rather than each computing it, and treat a sentinel that is indistinguishable from a real value as a failure at the point it is produced.
- **The cheapest step in a plan is deleting the step you were about to build.** Phase 3 specified a mechanical rewrite of all 71 step announcements so failures could be tagged. Thirty lines of probing showed `Get-PSCallStack` already carried the answer, including the case that looked hardest — a failure raised inside a helper, credited to the caller. The sweep vanished, and so did the problem the phase existed to solve, since attribution that never reads output cannot misread a child process's output. Probe the mechanism before executing a plan written against an assumed one; a plan is a hypothesis, and the expensive phases are the ones worth falsifying first.
- **No text scan can tell a control that runs from a comment claiming one.** The first implementation of the WQ-443 enforcement read each step's body looking for a planted defect. Run over all 70 steps it scored **step 69 — seven controls, two positive — as having none**, because three legitimate idioms are in use and any scan wide enough to accept all three also accepts prose. The enforceable version compares two declared lists exactly and makes the declaration expensive: a closed reason is valid only at or below a sealed step number, so a new step cannot inherit the grandfathering that covers the old ones. When a property cannot be observed statically, enforce a *declaration* and price it, rather than shipping a detector that cannot see.
- **A status field cannot hold a proof.** The registry's first schema had a `proven` status. A proof is the outcome of a run, so a file saying "proven" is stale the moment nobody runs the runner — the same inert-but-authoritative artifact the previous release spent itself removing. The field became `mutation`, naming the *specification* to execute; the exit code on the day it runs is the proof. Applies to any "verified", "reviewed" or "tested" flag stored next to the thing it describes.
- **A delete that raises no error is not a delete that happened.** `Directory.Delete` on a damaged exFAT entry returned cleanly and the directory was still there on the next probe. Every other attempt — `rd`, `Remove-Item`, rename, attribute write, `robocopy /MIR /B` with backup privilege — failed with `ERROR_ACCESS_DENIED` (5) on a filesystem that **has no ACLs**, which is the tell that separates a damaged entry from a held handle: a handle fails with `ERROR_SHARING_VIOLATION` (32). Two runs of `chkdsk /f`, one with a forced dismount, reported "no problems" throughout, so the filesystem's own checker is not a witness for this class. Confirm a destructive operation by re-reading the state, not by the absence of an exception — and read the error *number* before prescribing a remedy, because "permission denied" on a permissionless volume is not a permissions problem.
- **When a remedy has one step only the user can perform, split the steps — do not hand over the whole procedure.** `agent-defaults-always.mdc` already forbids ending with "run X to fix" when the agent can run X. It was violated anyway, twice in one session, because the remedy read as a single unit: physically re-seat a USB drive, *then* delete a directory. Only the first half needed a human. Bundling them turned one unavoidable hand-off into a wholesale offload, and the user had to push back to get the rest run. A procedure containing a human-only step is still mostly the agent's to execute.
- **Version control is optional to this pack, and the pack proves it.** Every functional git call guards for git's absence — `verify-work-queue.ps1` has three `[SKIP]` branches, `run_audit_core.ps1` returns `$null` without a `.git`, `check-requirements.ps1` marks git `Required $false`, and the audit's test-pass proof is a content fingerprint (`tree:<hash>`) that only *prefixes* HEAD when git happens to answer. CI strips `.git` and every permission bit and asserts the install still works on Linux and macOS. So a download, a folder copy and a flash drive are all first-class deliveries. **The execute bit is a convenience, not a requirement** — `bash install.sh` starts a file at mode 644 and the installer sets the bit on everything it writes. A clean audit and a green suite are the finish line here; whether the tree is committed is a separate question that no longer gates anything.
